// ---------- 짝지어 제거하기 -> Stack (맨 위와 같으면 pop, 아니면 push) ----------
// @tags: 스택/큐, 문자열
// @hint: no
// @solved: 2026-10-27
// @review: 2026-10-30, 2026-11-03
// @quiz: 같은 알파벳 두 개가 붙어 있으면 지우는 걸 반복해서 다 지워지는지 판단하려면? | Stack 에 넣으며 맨 위와 같으면 pop, 끝에 비었는지 확인 | 알파벳별 개수가 전부 짝수인지 확인 | 같은 쌍을 replace 로 지우고 처음부터 다시 | 앞뒤 투포인터로 양 끝이 같으면 지우기
// @why: 붙어 있는 쌍만 지울 수 있어서 개수가 짝수여도 실패할 수 있음(abab). 스택 맨 위 = 바로 앞에 남은 글자라 O(n)
// 문자를 하나씩 보면서
//   스택이 비어 있지 않고 맨 위가 지금 글자와 같으면 pop, 아니면 push
//   끝에 스택이 비어 있으면 성공
Stack<Character> stack = new Stack<>();
for (int i = 0; i < s.length(); i++) {
    char c = s.charAt(i);
    if (!stack.isEmpty() && c == stack.peek()) stack.pop();
    else stack.push(c);
}

// ---------- 괄호 회전하기 -> 회전은 인덱스 (x + j) % n, 짝 검사는 Stack ----------
// @tags: 스택/큐, 문자열
// @hint: yes
// @solved: 2026-10-27
// @review: 2026-10-30, 2026-11-03
// @quiz: 문자열을 실제로 돌리지 않고 x칸 왼쪽으로 회전한 문자열의 j번째 글자를 얻으려면? | s.charAt((x + j) % n) | s.charAt(x + j) | s.charAt((j - x) % n) | s.charAt(n - x + j)
// @why: 회전하면 j번째 자리에 원래 x+j번째가 오고, 끝을 넘으면 앞으로 돌아와야 해서 % n. (j - x) % n 은 음수가 될 수 있고 나머지는 범위를 넘음
// 문자열을 실제로 돌리지 않고 x칸 회전한 문자열의 j번째 = s.charAt((x + j) % n)
// 여는 괄호 push, 닫는 괄호면 (비었거나 짝 안 맞으면 실패) 아니면 pop, 끝에 비어 있으면 성공
// 큐로 회전 : queue.add(queue.poll())  -> 맨 앞을 맨 뒤로 = 왼쪽으로 한 칸 회전
//   큐를 n번 poll -> add 하며 훑으면 원래 순서로 돌아옴 (중간에 break 하면 순서 깨짐 -> boolean 으로 표시)
// 내 풀이 : 짝 안 맞으면 닫는 괄호도 그냥 push -> 맨 위에 닫는 괄호가 오면 다시는 pop 안 됨
//           -> 끝에 stack.isEmpty() 하나로 실패까지 같이 걸러짐
for (int i = 0; i < len; i++) {
    stack.clear();                                // 회전마다 스택 비우기
    for (int j = 0; j < len; j++) {
        char c = s.charAt((i + j) % len);
        if (!stack.isEmpty() && ((stack.peek() == '(' && c == ')')
                              || (stack.peek() == '[' && c == ']')
                              || (stack.peek() == '{' && c == '}'))) stack.pop();
        else stack.push(c);
    }
    if (stack.isEmpty()) answer++;
}

// ---------- n^2 배열 자르기 -> 배열 안 만들고 인덱스로 값 계산 (max(i, j) + 1) ----------
// @tags: 수학, 구현
// @hint: yes
// @solved: 2026-10-28
// @review: 2026-10-31, 2026-11-04
// @quiz: n x n 배열을 1차원으로 펼쳤을 때 k번째 칸의 값은? | Math.max(k / n, k % n) + 1 | Math.max(k % n, k / n) | Math.min(k / n, k % n) + 1 | (k / n) + (k % n) + 1
// @why: 행 i = k / n, 열 j = k % n 이고 표를 그려 보면 칸 값은 max(i, j) + 1. 인덱스가 0부터라 +1 을 빼먹기 쉬움
// 1차원 인덱스 k -> 행 i = k / n, 열 j = k % n  (2차원 <-> 1차원 변환 공식)
// 작은 n(3)으로 표를 그려 보면 칸의 값 = max(i, j) + 1
// 사고법 : 입력이 너무 크면 "다 만들고 꺼내기" 말고 "규칙 찾아서 바로 계산"
//          -> 작은 예시를 손으로 그려서 칸 값과 (i, j) 의 관계 찾기
// 복잡도 : O(right - left) (구간 길이 10^5 이하) -> n 이 10^7 이어도 상관없음
int[] answer = new int[(int) (right - left + 1)];
for (long k = left; k <= right; k++) {
    int i = (int) (k / n);                // 나눈 다음에 캐스팅
    int j = (int) (k % n);
    answer[(int) (k - left)] = Math.max(i, j) + 1;
}

// ---------- H-Index -> 오름차순 정렬 후 citations[i] >= n - i 인 첫 i 에서 h = n - i ----------
// @tags: 정렬
// @hint: yes
// @solved: 2026-10-29
// @review: 2026-11-01, 2026-11-05
// @quiz: citations = [10, 10, 10] 의 H-Index 와 그 이유는? | 3 (h 는 0 ~ n 범위에서 찾음) | 10 (배열 최댓값) | 0 (h 와 같은 인용수 논문이 없음) | 10 (배열에 있는 값 중 조건 맞는 최대)
// @why: h 는 "h번 이상 인용된 논문이 h편 이상"인 최대값. 논문이 3편뿐이라 h 는 3 을 넘을 수 없고, 배열에 없는 값이어도 됨
// h 의 범위는 0 ~ n (h편 이상이어야 하니 n 보다 클 수 없음). 배열 값만 후보로 잡지 않기
// 방법 1 (완전탐색, n <= 1000 이라 충분) : h 를 n 부터 0 까지 내려가며 h번 이상 인용된 논문 수 >= h 면 바로 return
// 방법 2 (정렬) : 오름차순 정렬 후 citations[i] >= n - i 가 처음 되는 i 에서 h = n - i
//   (n - i = citations[i] 이상인 논문 수)
Arrays.sort(citations);
int n = citations.length;
for (int i = 0; i < n; i++) {
    if (citations[i] >= n - i) return n - i;   // 남은 논문 수(n - i)가 h
}

// ---------- 피로도 -> 순열 완전탐색 (재귀 + visited + 되돌리기) ----------
// @tags: 완전탐색, DFS, 백트래킹
// @hint: yes
// @solved: 2026-10-29
// @review: 2026-11-01, 2026-11-05
// @quiz: 던전 최대 8개를 도는 순서 중 가장 많이 도는 경우를 찾으려면? | 재귀 + visited 로 모든 순서(순열) 시도 | 필요 피로도가 큰 순으로 정렬해서 그리디 | 이중 for문으로 시작 던전만 바꿔서 시도 | 소모 피로도가 작은 순으로 정렬해서 그리디
// @why: 8! = 40,320 이라 전부 해봐도 빠름. 정렬 그리디는 반례가 있고, 이중 for문은 시작만 바뀌고 나머지 순서는 고정
// 던전 최대 8개 -> 8! = 40,320 가지 순서를 전부 해봐도 충분
// 갈 수 있는 던전 하나 골라 들어가고 나머지는 재귀에 맡김. 매 호출마다 지금까지 개수로 answer 갱신
// "중간부터 시작해서 앞으로" 같은 임의의 순서가 필요하면 이중 for문 말고 이 패턴
// 왜 무한히 안 도나 : 호출마다 visited 가 하나씩 늘어 깊이는 최대 n. 갈 데 없으면 for 가 다 continue -> 그냥 return
// 디버깅 : "    ".repeat(count) 로 들여쓰기 해서 진입/선택 시점에 println 하면 트리 모양으로 보임
// 원복 규칙 : 매개변수(k, count)는 호출마다 따로 생김 -> k - cost 처럼 새 값을 넘기면 원복 필요 없음
//            필드(visited)는 모든 호출이 같이 씀 -> 바꿨으면 false 로 직접 원복
//            (k -= cost 로 k 자체를 바꿨다면 dfs 뒤에 k += cost 필요)
void dfs(int k, int count, int[][] dungeons) {
    answer = Math.max(answer, count);
    for (int i = 0; i < dungeons.length; i++) {
        if (visited[i] || k < dungeons[i][0]) continue;   // 이미 갔거나 피로도 부족
        visited[i] = true;
        dfs(k - dungeons[i][1], count + 1, dungeons);      // count++ 아님
        visited[i] = false;                                // 되돌리기
    }
}

// ---------- 행렬의 곱셈 -> 3중 for문 (i 행, j 열, k 겹치는 길이) ----------
// @tags: 수학, 구현
// @hint: no
// @solved: 2026-10-29
// @review: 2026-11-01, 2026-11-05
// @quiz: (a x b) 행렬과 (b x c) 행렬을 곱한 결과 배열 크기는? | new int[arr1.length][arr2[0].length] | new int[arr1.length][arr2.length] | new int[arr1[0].length][arr2[0].length] | new int[arr2.length][arr1[0].length]
// @why: 결과는 (a x c). a = arr1 행 수 = arr1.length, c = arr2 열 수 = arr2[0].length. 겹치는 b 는 사라짐
// (a x b) * (b x c) = (a x c). 곱할 수 있는 조건 : arr1[0].length == arr2.length (= k 범위)
// 결과 크기 : new int[arr1.length][arr2[0].length]
// answer[i][j] = arr1 의 i행과 arr2 의 j열을 같은 k 끼리 곱해서 전부 더한 값
// int 배열은 0 으로 초기화돼 있으니 바로 += 해도 됨
int[][] answer = new int[arr1.length][arr2[0].length];
for (int i = 0; i < arr1.length; i++)
    for (int j = 0; j < arr2[0].length; j++)
        for (int k = 0; k < arr1[0].length; k++)   // arr2.length 로 써도 같음
            answer[i][j] += arr1[i][k] * arr2[k][j];

// ---------- 다음 큰 숫자 -> 1씩 올려 가며 bitCount 비교 ----------
// @tags: 비트/진법
// @hint: no
// @solved: 2026-10-27
// @review: 2026-10-30, 2026-11-03
// @quiz: n 보다 크고 2진수 1의 개수가 같은 가장 작은 수를 구하려면? | n+1 부터 1씩 올리며 Integer.bitCount 가 같으면 바로 return | 1의 개수가 같은 수를 전부 모은 뒤 최솟값 | toBinaryString 을 뒤집어서 parseInt(s, 2) | n * 2 를 return
// @why: 작은 쪽부터 올라가니까 처음 맞는 수가 곧 최솟값. 뒤집기나 *2 는 1의 개수는 같아도 "가장 작은 큰 수"가 아님
// 작은 쪽부터 올라가니까 처음 조건에 맞는 수가 곧 최솟값 (따로 최솟값 찾을 필요 없음)
int ones = Integer.bitCount(n);
int next = n + 1;
while (Integer.bitCount(next) != ones) next++;
// return next;

// ---------- 숫자의 표현 -> 시작점마다 연속으로 더해 보기 ----------
// @tags: 완전탐색, 수학
// @hint: no
// @solved: 2026-10-27
// @review: 2026-10-30, 2026-11-03
// @quiz: 연속된 자연수의 합으로 n 을 나타내는 방법 수를 셀 때, 시작점마다 더하다가 언제 멈출까? | sum == n 이면 +1 하고, sum > n 이 되면 다음 시작점으로 | sum == n 일 때만 멈추고 끝까지 더하기 | i < n 까지 더해 보고 마지막에 sum == n 비교 | sum 을 시작점 밖에서 한 번만 0 으로 두고 계속 누적
// @why: 자연수만 더하니 sum 은 계속 커짐 -> 넘으면 더 볼 필요 없음. sum 은 시작점마다 0 으로, 끝은 n 자신까지(<=)
for (int start = 1; start <= n; start++) {
    int sum = 0;                          // 시작점이 바뀔 때마다 0 으로 초기화
    for (int i = start; i <= n; i++) {
        sum += i;
        if (sum == n) { answer++; break; }   // 같으면 방법 +1
        if (sum > n) break;                  // 넘으면 다음 시작점으로
    }
}

// ---------- 피보나치 수 -> 변수 두 개를 한 칸씩 밀기 + 매번 % ----------
// @tags: DP, 수학
// @hint: no
// @solved: 2026-10-27
// @review: 2026-10-30, 2026-11-03
// @quiz: n 이 10만일 때 피보나치를 구하는 방법으로 맞는 것은? | 변수 두 개를 밀면서 매 단계 % 1234567 | 재귀 fib(n-1) + fib(n-2) | long 배열에 다 저장하고 마지막에 % | 재귀로 구하고 마지막에 %
// @why: 단순 재귀는 같은 계산을 지수적으로 반복해서 시간 초과(+ 스택 오버플로우). 마지막에만 % 하면 long 도 넘침
// first, second 는 "가장 최근 연속된 두 항". 밀 때 순서가 중요함
int first = 0, second = 1, cur = 0;
for (int i = 2; i <= n; i++) {
    cur = (first + second) % 1234567;     // 더하면서 바로 나머지
    first = second;                       // 먼저 first 를 옮기고
    second = cur;                         // 그다음 second 를 갱신
}

// ---------- 롤케이크 자르기 -> 오른쪽 HashMap(개수) + 왼쪽 HashSet ----------
// @tags: 해시
// @hint: no
// @solved: 2026-10-29
// @review: 2026-11-01, 2026-11-05
// @quiz: 토핑 100만 개 롤케이크를 자를 때마다 양쪽 토핑 종류 수를 비교하려면? | 전부 오른쪽 map(개수)에 넣고 한 칸씩 왼쪽 set 으로 옮기기 | 자르는 위치마다 양쪽을 HashSet 으로 새로 만들어 size 비교 | 정렬한 뒤 가운데에서 자르기 | 자를 때마다 Arrays.copyOfRange 로 나눠서 distinct().count()
// @why: 위치마다 새로 세면 O(n^2) 시간 초과. 한 칸씩 옮기면 O(n). 개수가 0 이 되면 map 에서 remove 해야 size 가 종류 수
// 자르는 위치마다 양쪽 종류 수를 새로 세면 O(n^2) -> 시간 초과
// 처음에 전부 오른쪽(map)에 개수로 넣고, 한 칸씩 왼쪽(set)으로 옮기면 O(n)
// map 은 "남은 개수", set 은 "있냐 없냐"만 필요 -> 종류 수 = size()
// 개수가 0 이 되면 꼭 remove 해야 map.size() 가 종류 수가 됨
Map<Integer, Integer> right = new HashMap<>();
Set<Integer> left = new HashSet<>();
for (int t : topping) right.put(t, right.getOrDefault(t, 0) + 1);
for (int t : topping) {
    left.add(t);
    right.put(t, right.get(t) - 1);
    if (right.get(t) == 0) right.remove(t);    // 0 남은 키 지우기
    if (left.size() == right.size()) answer++;
}

// ---------- [1차] 캐시 -> LRU (가장 오래 안 쓴 것부터 버리기) ----------
// @tags: 시뮬레이션, 스택/큐
// @hint: yes
// @solved: 2026-10-29
// @review: 2026-11-01, 2026-11-05
// @quiz: LRU 캐시에서 이미 있는 도시가 또 들어오면(hit) 어떻게 할까? | +1 하고 그 도시를 빼서 맨 뒤로 다시 넣기 | +1 만 하고 위치는 그대로 | +5 하고 맨 앞을 버린 뒤 맨 뒤에 넣기 | +1 하고 맨 앞(가장 오래된 것)을 버리기
// @why: LRU 는 "가장 오래 안 쓴 것"을 버리니까 방금 쓴 건 최근 쪽(맨 뒤)으로 옮겨야 함. 그대로 두면 FIFO 가 됨
// 캐시 = 순서가 있는 리스트. 앞쪽 = 가장 오래 안 쓴 것, 뒤쪽 = 방금 쓴 것
// hit (이미 있음)  : +1, 그 도시를 리스트에서 빼서 맨 뒤로 다시 넣기 (최근 사용으로 갱신)
// miss (없음)      : +5, 꽉 찼으면 맨 앞(가장 오래된 것)을 버리고 맨 뒤에 넣기
// 대소문자 구분 X -> 비교 전에 toLowerCase() 로 통일 ("Jeju" == "jeju")
// cacheSize == 0 이면 캐시에 아무것도 못 넣음 -> 전부 miss (도시 수 * 5). 빈 리스트에서 꺼내다 에러 주의
// 도구 : LinkedList<String> 의 contains / remove(Object) / removeFirst / addLast
//        (cacheSize 최대 30 이라 contains 의 O(n) 도 충분히 빠름)

// ---------- 게임 맵 최단거리 -> BFS (격자 최단거리, dist[][] + 4방향) ----------
// @tags: BFS, 그래프
// @hint: yes
// @solved: 2026-11-01
// @review: 2026-11-04, 2026-11-08
// @quiz: BFS 에서 각 칸까지의 최단거리를 기록하는 올바른 방법은? | dist[새칸] = dist[지금칸] + 1 | 큐에서 꺼낼 때마다 count++ | 큐에 넣을 때마다 count++ | 4방향을 다 볼 때마다 count++
// @why: 갈래가 여러 개라 count 하나로는 "꺼낸/넣은 칸 개수"가 섞임. 칸마다 자기 거리를 따로 저장해야 함 (count 를 쓰려면 queue.size() 만큼 한 겹씩 처리)
// BFS(너비 우선) vs DFS(깊이 우선)
//   DFS : 한 길을 끝까지 가보고 막히면 되돌아옴 (재귀 / Stack) -> 모든 경우, 순열/조합
//   BFS : 가까운 칸부터 한 겹씩 (1칸 -> 2칸 -> 3칸) 넓혀감 (Queue, FIFO) -> 최단거리
//   Queue 라서 먼저 넣은(가까운) 칸이 먼저 나옴 -> 거리 순서가 자동으로 지켜짐
// "최단거리 / 최소 칸 수" + 모든 칸 이동 비용이 같음 -> BFS
// BFS 는 1칸, 2칸, 3칸 ... 거리 순서대로 퍼짐 -> 도착점에 "처음" 닿는 순간이 최단거리
// DFS(완전탐색)는 모든 경로를 끝까지 가봄 -> 맞긴 해도 맵이 크면 시간 초과
// 틀 : Queue<int[]> 에 {행, 열} 넣기 + dist[][] 에 "여기까지 몇 칸" 저장 (dist 가 visited 역할도 함)
//      꺼낼 때마다 dx/dy 4방향 -> 범위 안 && 벽 아님 && 처음 방문이면 dist = 현재 + 1, 큐에 넣기
//      큐가 빌 때까지 도착점에 못 닿으면 -1
// 넣을 때 방문 처리해야 같은 칸이 큐에 여러 번 안 들어감
// dist[x][y] = 시작점에서 (x, y) 까지 몇 칸. dist[새칸] = dist[지금칸] + 1
//   꺼낼 때마다 count++ 하면 X : 그건 거리가 아니라 "꺼낸 칸 총개수" (갈래가 여러 개라 섞임)
//   count 를 쓰고 싶으면 int size = queue.size(); 만큼 한 겹 처리하고 겹이 끝날 때 count++

// ---------- 프로세스 -> Queue<int[]>{인덱스, 우선순위} + "더 큰 게 남았나" 검사 ----------
// @tags: 스택/큐
// @hint: yes
// @solved: 2026-11-01
// @review: 2026-11-04, 2026-11-08
// @quiz: 꺼낸 프로세스보다 우선순위가 높은 게 큐에 남아 있으면 어떻게 할까? | 다시 큐 맨 뒤에 넣고, 실행 횟수는 그대로 | 다시 넣고 실행 횟수 +1 | 우선순위 높은 걸 찾아서 바로 실행 | priorities 를 내림차순 정렬해서 location 의 위치를 답으로
// @why: 뒤로 보낸 건 실행된 게 아니라서 세면 안 됨. 정렬하면 같은 우선순위끼리의 큐 순서가 사라져서 틀림
// 맨 앞을 꺼내서 뒤에 더 큰 우선순위가 있으면 다시 뒤로(add), 없으면 실행(count++)
// 실행한 게 location 이면 그때의 count 가 답 -> 바로 return (실행 순서 배열 따로 필요 없음)
// 핵심 : 원소가 뒤로 돌면 위치가 바뀌니까 "원래 인덱스"를 원소와 같이 저장
// 더 큰 값 검사 : queue.stream().anyMatch(p -> p[1] > cur[1])  (n <= 100 이라 매번 훑어도 충분)
// 심화 : 우선순위만 PriorityQueue(Collections.reverseOrder()) 에 넣어 두면 pq.peek() 가 "지금 최댓값"
//        실행할 때마다 pq.poll() 로 같이 빼기
Queue<int[]> queue = new LinkedList<>();               // {원래 인덱스, 우선순위}
for (int i = 0; i < priorities.length; i++) queue.add(new int[]{i, priorities[i]});
int proceed = 1;
while (!queue.isEmpty()) {
    int[] cur = queue.poll();
    if (queue.stream().anyMatch(x -> x[1] > cur[1])) queue.add(cur);   // 더 큰 게 있으면 뒤로
    else {
        if (cur[0] == location) return proceed;      // 실행된 경우에만 확인
        proceed++;
    }
}

// ---------- 튜플 -> 집합을 원소 개수 순으로 정렬하고, 새로 등장한 숫자만 차례로 담기 ----------
// @tags: 문자열, 정렬, 해시
// @hint: no
// @solved: 2026-11-02
// @review: 2026-11-05, 2026-11-09
// @quiz: "{{2},{2,1},{2,1,3}}" 같은 집합 문자열에서 튜플 순서를 알아내려면? | 집합을 원소 개수 순으로 정렬하고, 앞에서부터 새로 나온 숫자만 담기 | 숫자들을 전부 꺼내서 오름차순 정렬하기 | 문자열에 나온 순서대로 중복만 빼고 담기 | 각 집합의 첫 번째 숫자를 차례로 담기
// @why: 크기 k 집합 = 튜플 앞 k 개라서, 작은 집합부터 보면 매번 딱 하나씩 새 숫자가 생김. 입력은 집합 순서도 집합 안 원소 순서도 섞여 있어서 나온 순서/첫 원소/숫자 크기는 믿으면 안 됨
// 입력 순서는 뒤죽박죽 ("{{4,2,3},{3},{2,3,4,1},{2,3}}") -> 집합 크기로 정렬해야 순서가 생김
// 크기 1 집합의 원소 = 1번째, 크기 2 집합에서 새로 생긴 원소 = 2번째 ... (매번 정확히 1개만 새로 생김)
// 파싱 : 바깥 "{{" "}}" 를 substring(2, len - 2) 로 떼고, "},{" 를 구분자로 바꿔 split
// 문자열 길이로 정렬해도 OK : 다음 집합은 앞 집합 + 숫자 하나 + 쉼표 하나라서 항상 더 김
//   (더 안전하게 하려면 split(",").length 로 원소 개수 비교)
// 이미 담은 숫자는 HashSet 으로 걸러내기 (contains O(1))
// 다른 풀이 : 숫자마다 등장 횟수를 세면 많이 나온 숫자일수록 앞 (1번째 원소는 n 번, 마지막은 1 번)
String str = s.substring(2, s.length() - 2).replace("},{", "-");
String[] sets = str.split("-");
Arrays.sort(sets, (a, b) -> a.length() - b.length());   // 원소 적은 집합부터
int[] answer = new int[sets.length];
Set<String> seen = new HashSet<>();
for (int i = 0; i < sets.length; i++) {
    for (String num : sets[i].split(",")) {
        if (seen.add(num)) {                  // add 는 새로 들어가면 true
            answer[i] = Integer.parseInt(num);
            break;                            // 새 숫자는 딱 하나라 바로 끝
        }
    }
}
