# 코테 노트

프로그래머스 Java 풀이 정리 파일(`content/코테_누적정리.txt`)을 웹과 모바일에서 보기 좋게 보여 주는 앱입니다.
문제별·유형별 필터, 검색, 힌트 본 문제와 복습일 표시, 코드 하이라이팅, 복습용 객관식 퀴즈가 있습니다.

## 내용 업데이트

`content/코테_누적정리.txt` 를 새 파일로 바꿔서 `main` 에 올리면 1~2분 뒤 사이트가 자동으로 갱신됩니다.
GitHub 웹에서 `content` 폴더 → **Add file → Upload files** 로 같은 이름의 파일을 올려도 됩니다.
휴대폰에 설치한 앱은 다음에 열 때 "업데이트됐어요" 알림이 뜹니다.

## 파일 규칙

지금 쓰는 형식을 그대로 읽습니다.

| 파일의 모양 | 화면에서 |
| --- | --- |
| `// ====` 사이의 `// N. 제목` | 섹션 (치트시트, 실수/팁, 틀렸던 포인트, 문제, 우선순위) |
| `// ---------- 문제명 -> 핵심 ----------` | 문제 카드 하나 |
| 헤더 다음 `//` 주석 줄 | 핵심 개념 (`// 내 풀이 :` 로 시작하면 따로 강조) |
| 주석이 아닌 줄부터 | 코드 (하이라이팅 + 복사) |
| 틀렸던 포인트 `- ... (의상)` | 괄호 안 문제 이름으로 그 문제 카드에 연결 |
| 치트시트 `코드   // 설명` | 메소드 표 한 줄 + 퀴즈 |

### 선택 메타데이터 (문제 헤더 바로 아래)

```java
// ---------- 게임 맵 최단거리 -> BFS (격자 최단거리) ----------
// @tags: BFS, 그래프          (없으면 키워드로 자동 추론, 화면에 "자동" 표시)
// @hint: yes                  (힌트/풀이를 봤으면 yes)
// @review: 2026-11-08         (복습일, 여러 개면 쉼표)
// @solved: 2026-10-28         (푼 날짜)
// @level: 2
// @quiz: BFS 에 쓰는 자료구조는? | Queue | Stack | PriorityQueue   (질문 | 정답 | 오답...)
// @why: 먼저 넣은 칸을 먼저 꺼내야 가까운 칸부터 퍼짐     (선택: 풀고 나서 보여 줄 해설)
// @terms: LRU = 가장 오래 안 쓴 것부터 버리기 | hit = 이미 있음   (선택: 퀴즈 "용어 힌트"에 항상 보일 용어)
```

설명 줄 중 `hit (이미 있음) : ...`, `캐시 = ...` 처럼 짧은 이름 뒤에 `:` 나 `=` 가 오는 줄은 용어로 자동 인식합니다.
자동 용어는 퀴즈 카드에 그 말이 나올 때만 "용어 힌트 보기"에 나오고, 정답을 거의 그대로 담은 줄은 빠집니다.

### 틀렸던 포인트 퀴즈

틀렸던 포인트는 `실수 -> 결과 => 고치는 법` 을 알아서 나눠서 문제로 만듭니다.

- `-> 시간 초과`, `-> 에러` 처럼 **결과**를 말하는 조각은 질문 쪽에 붙고, 남는 조각이 **고치는 법** 보기가 됩니다.
- 고치는 법이 없고 결과만 있으면 "이렇게 하면 어떻게 될까?" 문제가 됩니다.
- 끝에 띄어 쓴 괄호 `( (a + b) % m == ... )` 는 보기에서 빼고 해설로 보여 줍니다.
- 카드 위에 어느 문제의 실수인지(문제명 · 한 줄 요약)가 나옵니다.
- 오답 보기는 같은 문제의 다른 메모에서 먼저, 모자라면 같은 유형 문제의 메모에서만 고릅니다.
- 그래도 3개가 안 되면 객관식 대신 "떠올려 보고 정답 보기" 카드로 나옵니다 (기억났어요 / 몰랐어요로 기록).

자동 보기가 어색한 항목은 그 항목 바로 아래에 `@quiz` 를 적으면 자동 문제 대신 나갑니다.
오답을 "그럴듯하게 틀린 방법"으로 직접 쓰면 제일 좋은 문제가 됩니다.

```java
// - 값이 너무 커지는 문제 : 마지막에만 % 하면 이미 int 오버플로우
//       -> 계산할 때마다 중간중간 %
//       @quiz: 답을 1234567 로 나눈 나머지로 내라는 문제. 오버플로우 없이 맞게 하려면? | 더하거나 곱할 때마다 바로 % 하기 | 다 계산한 뒤 마지막에 한 번만 % 하기 | int 대신 double 로 계산하기
//       @why: (a + b) % m == ((a % m) + (b % m)) % m 이라 중간에 나눠도 답이 같음
```

복습 완료 체크, 퀴즈 기록(푼 판·고른 답), 풀던 퀴즈는 각 기기(브라우저)에 저장됩니다. 다른 화면에 갔다 와도 풀던 퀴즈가 이어집니다.

## 올리기 전에 확인

```bash
npm install
npm run check        # 파일을 어떻게 읽었는지 요약 + 형식 경고
npm run dev          # 로컬에서 보기
```

## 기술

React + TypeScript (Vite), Tailwind CSS, Shiki (빌드 때 Java 하이라이팅), Fuse.js (검색), vite-plugin-pwa (홈 화면 설치·오프라인), GitHub Pages + Actions.
