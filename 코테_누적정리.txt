// - cacheSize == 0 처리 안 함 -> 빈 큐 poll() 은 null, 그다음 add 로 1개가 들어가 hit(+1) 로 잘못 셈 (캐시)

// ---------- 짝지어 제거하기 -> Stack (맨 위와 같으면 pop, 아니면 push) ----------
// @tags: 스택/큐, 문자열
// @hint: no
// @solved: 2026-10-27
// @review: 2026-10-30, 2026-11-03
// @quiz: 같은 알파벳 두 개가 붙어 있으면 지우는 걸 반복해서 다 지워지는지 판단하려면? | Stack 에 넣으며 맨 위와 같으면 pop, 끝에 비었는지 확인 | 알파벳별 개수가 전부 짝수인지 확인 | 같은 쌍을 replace 로 지우고 처음부터 다시 | 앞뒤 투포인터로 양 끝이 같으면 지우기
// @why: 붙어 있는 쌍만 지울 수 있어서 개수가 짝수여도 실패할 수 있음(abab). 스택 맨 위 = 바로 앞에 남은 글자라 O(n)
// 문자를 하나씩 보면서
//   스택이 비어 있지 않고 맨 위가 지금 글자와 같으면 pop, 아니면 push
//   끝에 스택이 비어 있으면 성공
Stack<Character> stack = new Stack<>();
for (int i = 0; i < s.length(); i++) {
    char c = s.charAt(i);
    if (!stack.isEmpty() && c == stack.peek()) stack.pop();
    else stack.push(c);
}

// ---------- 괄호 회전하기 -> 회전은 인덱스 (x + j) % n, 짝 검사는 Stack ----------
// @tags: 스택/큐, 문자열
// @hint: yes
// @solved: 2026-10-27
// @review: 2026-10-30, 2026-11-03
// @quiz: 문자열을 실제로 돌리지 않고 x칸 왼쪽으로 회전한 문자열의 j번째 글자를 얻으려면? | s.charAt((x + j) % n) | s.charAt(x + j) | s.charAt((j - x) % n) | s.charAt(n - x + j)
// @why: 회전하면 j번째 자리에 원래 x+j번째가 오고, 끝을 넘으면 앞으로 돌아와야 해서 % n. (j - x) % n 은 음수가 될 수 있고 나머지는 범위를 넘음
// 문자열을 실제로 돌리지 않고 x칸 회전한 문자열의 j번째 = s.charAt((x + j) % n)
// 여는 괄호 push, 닫는 괄호면 (비었거나 짝 안 맞으면 실패) 아니면 pop, 끝에 비어 있으면 성공
// 큐로 회전 : queue.add(queue.poll())  -> 맨 앞을 맨 뒤로 = 왼쪽으로 한 칸 회전
//   큐를 n번 poll -> add 하며 훑으면 원래 순서로 돌아옴 (중간에 break 하면 순서 깨짐 -> boolean 으로 표시)
// 내 풀이 : 짝 안 맞으면 닫는 괄호도 그냥 push -> 맨 위에 닫는 괄호가 오면 다시는 pop 안 됨
//           -> 끝에 stack.isEmpty() 하나로 실패까지 같이 걸러짐
for (int i = 0; i < len; i++) {
    stack.clear();                                // 회전마다 스택 비우기
    for (int j = 0; j < len; j++) {
        char c = s.charAt((i + j) % len);
        if (!stack.isEmpty() && ((stack.peek() == '(' && c == ')')
                              || (stack.peek() == '[' && c == ']')
                              || (stack.peek() == '{' && c == '}'))) stack.pop();
        else stack.push(c);
    }
    if (stack.isEmpty()) answer++;
}

// ---------- n^2 배열 자르기 -> 배열 안 만들고 인덱스로 값 계산 (max(i, j) + 1) ----------
// @tags: 수학, 구현
// @hint: yes
// @solved: 2026-10-28
// @review: 2026-10-31, 2026-11-04
// @quiz: n x n 배열을 1차원으로 펼쳤을 때 k번째 칸의 값은? | Math.max(k / n, k % n) + 1 | Math.max(k % n, k / n) | Math.min(k / n, k % n) + 1 | (k / n) + (k % n) + 1
// @why: 행 i = k / n, 열 j = k % n 이고 표를 그려 보면 칸 값은 max(i, j) + 1. 인덱스가 0부터라 +1 을 빼먹기 쉬움
// 1차원 인덱스 k -> 행 i = k / n, 열 j = k % n  (2차원 <-> 1차원 변환 공식)
// 작은 n(3)으로 표를 그려 보면 칸의 값 = max(i, j) + 1
// 사고법 : 입력이 너무 크면 "다 만들고 꺼내기" 말고 "규칙 찾아서 바로 계산"
//          -> 작은 예시를 손으로 그려서 칸 값과 (i, j) 의 관계 찾기
// 복잡도 : O(right - left) (구간 길이 10^5 이하) -> n 이 10^7 이어도 상관없음
int[] answer = new int[(int) (right - left + 1)];
for (long k = left; k <= right; k++) {
    int i = (int) (k / n);                // 나눈 다음에 캐스팅
    int j = (int) (k % n);
    answer[(int) (k - left)] = Math.max(i, j) + 1;
}

// ---------- H-Index -> 오름차순 정렬 후 citations[i] >= n - i 인 첫 i 에서 h = n - i ----------
// @tags: 정렬
// @hint: yes
// @solved: 2026-10-29
// @review: 2026-11-01, 2026-11-05
// @quiz: citations = [10, 10, 10] 의 H-Index 와 그 이유는? | 3 (h 는 0 ~ n 범위에서 찾음) | 10 (배열 최댓값) | 0 (h 와 같은 인용수 논문이 없음) | 10 (배열에 있는 값 중 조건 맞는 최대)
// @why: h 는 "h번 이상 인용된 논문이 h편 이상"인 최대값. 논문이 3편뿐이라 h 는 3 을 넘을 수 없고, 배열에 없는 값이어도 됨
// h 의 범위는 0 ~ n (h편 이상이어야 하니 n 보다 클 수 없음). 배열 값만 후보로 잡지 않기
// 방법 1 (완전탐색, n <= 1000 이라 충분) : h 를 n 부터 0 까지 내려가며 h번 이상 인용된 논문 수 >= h 면 바로 return
// 방법 2 (정렬) : 오름차순 정렬 후 citations[i] >= n - i 가 처음 되는 i 에서 h = n - i
//   (n - i = citations[i] 이상인 논문 수)
Arrays.sort(citations);
int n = citations.length;
for (int i = 0; i < n; i++) {
    if (citations[i] >= n - i) return n - i;   // 남은 논문 수(n - i)가 h
}

// @review: 2026-11-01, 2026-11-05
// @quiz: 던전 최대 8개를 도는 순서 중 가장 많이 도는 경우를 찾으려면? | 재귀 + visited 로 모든 순서(순열) 시도 | 필요 피로도가 큰 순으로 정렬해서 그리디 | 이중 for문으로 시작 던전만 바꿔서 시도 | 소모 피로도가 작은 순으로 정렬해서 그리디
// @why: 8! = 40,320 이라 전부 해봐도 빠름. 정렬 그리디는 반례가 있고, 이중 for문은 시작만 바뀌고 나머지 순서는 고정
// 던전 최대 8개 -> 8! = 40,320 가지 순서를 전부 해봐도 충분
// 갈 수 있는 던전 하나 골라 들어가고 나머지는 재귀에 맡김. 매 호출마다 지금까지 개수로 answer 갱신
// "중간부터 시작해서 앞으로" 같은 임의의 순서가 필요하면 이중 for문 말고 이 패턴
// 왜 무한히 안 도나 : 호출마다 visited 가 하나씩 늘어 깊이는 최대 n. 갈 데 없으면 for 가 다 continue -> 그냥 return
// 디버깅 : "    ".repeat(count) 로 들여쓰기 해서 진입/선택 시점에 println 하면 트리 모양으로 보임
// 원복 규칙 : 매개변수(k, count)는 호출마다 따로 생김 -> k - cost 처럼 새 값을 넘기면 원복 필요 없음
//            필드(visited)는 모든 호출이 같이 씀 -> 바꿨으면 false 로 직접 원복
//            (k -= cost 로 k 자체를 바꿨다면 dfs 뒤에 k += cost 필요)
void dfs(int k, int count, int[][] dungeons) {
    answer = Math.max(answer, count);
    for (int i = 0; i < dungeons.length; i++) {
        if (visited[i] || k < dungeons[i][0]) continue;   // 이미 갔거나 피로도 부족
        visited[i] = true;
        dfs(k - dungeons[i][1], count + 1, dungeons);      // count++ 아님
        visited[i] = false;                                // 되돌리기
    }
}

// ---------- 행렬의 곱셈 -> 3중 for문 (i 행, j 열, k 겹치는 길이) ----------
// @tags: 수학, 구현
// @hint: no
// @solved: 2026-10-29
// @review: 2026-11-01, 2026-11-05
// @quiz: (a x b) 행렬과 (b x c) 행렬을 곱한 결과 배열 크기는? | new int[arr1.length][arr2[0].length] | new int[arr1.length][arr2.length] | new int[arr1[0].length][arr2[0].length] | new int[arr2.length][arr1[0].length]
// @why: 결과는 (a x c). a = arr1 행 수 = arr1.length, c = arr2 열 수 = arr2[0].length. 겹치는 b 는 사라짐
// (a x b) * (b x c) = (a x c). 곱할 수 있는 조건 : arr1[0].length == arr2.length (= k 범위)
// 결과 크기 : new int[arr1.length][arr2[0].length]
// answer[i][j] = arr1 의 i행과 arr2 의 j열을 같은 k 끼리 곱해서 전부 더한 값
// int 배열은 0 으로 초기화돼 있으니 바로 += 해도 됨
int[][] answer = new int[arr1.length][arr2[0].length];
for (int i = 0; i < arr1.length; i++)
    for (int j = 0; j < arr2[0].length; j++)
        for (int k = 0; k < arr1[0].length; k++)   // arr2.length 로 써도 같음
            answer[i][j] += arr1[i][k] * arr2[k][j];

// ---------- 숫자의 표현 -> 시작점마다 연속으로 더해 보기 ----------
// @tags: 완전탐색, 수학
// @hint: no
// @solved: 2026-10-27
// @review: 2026-10-30, 2026-11-03
// @quiz: 연속된 자연수의 합으로 n 을 나타내는 방법 수를 셀 때, 시작점마다 더하다가 언제 멈출까? | sum == n 이면 +1 하고, sum > n 이 되면 다음 시작점으로 | sum == n 일 때만 멈추고 끝까지 더하기 | i < n 까지 더해 보고 마지막에 sum == n 비교 | sum 을 시작점 밖에서 한 번만 0 으로 두고 계속 누적
// @why: 자연수만 더하니 sum 은 계속 커짐 -> 넘으면 더 볼 필요 없음. sum 은 시작점마다 0 으로, 끝은 n 자신까지(<=)
for (int start = 1; start <= n; start++) {
    int sum = 0;                          // 시작점이 바뀔 때마다 0 으로 초기화
    for (int i = start; i <= n; i++) {
        sum += i;
        if (sum == n) { answer++; break; }   // 같으면 방법 +1
        if (sum > n) break;                  // 넘으면 다음 시작점으로
    }
}

// @why: 위치마다 새로 세면 O(n^2) 시간 초과. 한 칸씩 옮기면 O(n). 개수가 0 이 되면 map 에서 remove 해야 size 가 종류 수
// 자르는 위치마다 양쪽 종류 수를 새로 세면 O(n^2) -> 시간 초과

Map<Integer, Integer> right = new HashMap<>();
Set<Integer> left = new HashSet<>();
for (int t : topping) right.put(t, right.getOrDefault(t, 0) + 1);
for (int t : topping) {
    left.add(t);
    right.put(t, right.get(t) - 1);
    if (right.get(t) == 0) right.remove(t);    // 0 남은 키 지우기
    if (left.size() == right.size()) answer++;

// ---------- [1차] 캐시 -> LRU (가장 오래 안 쓴 것부터 버리기) ----------
// @tags: 시뮬레이션, 스택/큐
// @hint: yes
// @solved: 2026-10-29
// @review: 2026-11-01, 2026-11-05
// @quiz: LRU 캐시에서 이미 있는 도시가 또 들어오면(hit) 어떻게 할까? | +1 하고 그 도시를 빼서 맨 뒤로 다시 넣기 | +1 만 하고 위치는 그대로 | +5 하고 맨 앞을 버린 뒤 맨 뒤에 넣기 | +1 하고 맨 앞(가장 오래된 것)을 버리기
// @why: LRU 는 "가장 오래 안 쓴 것"을 버리니까 방금 쓴 건 최근 쪽(맨 뒤)으로 옮겨야 함. 그대로 두면 FIFO 가 됨
// 캐시 = 순서가 있는 리스트. 앞쪽 = 가장 오래 안 쓴 것, 뒤쪽 = 방금 쓴 것
// hit (이미 있음)  : +1, 그 도시를 리스트에서 빼서 맨 뒤로 다시 넣기 (최근 사용으로 갱신)
// miss (없음)      : +5, 꽉 찼으면 맨 앞(가장 오래된 것)을 버리고 맨 뒤에 넣기
// 대소문자 구분 X -> 비교 전에 toLowerCase() 로 통일 ("Jeju" == "jeju")
// cacheSize == 0 이면 캐시에 아무것도 못 넣음 -> 전부 miss (도시 수 * 5). 빈 리스트에서 꺼내다 에러 주의
// 도구 : LinkedList<String> 의 contains / remove(Object) / removeFirst / addLast
//        (cacheSize 최대 30 이라 contains 의 O(n) 도 충분히 빠름)
// 내 풀이 (hit/miss 4갈래 분기, 크기 조건은 사실 miss 일 때만 필요)
Queue<String> queue = new LinkedList<>();
for (String str : cities) {
    if (cacheSize == 0) return cities.length * 5;      // 크기 0 이면 전부 miss
    String city = str.toLowerCase();
    if (queue.size() < cacheSize && !queue.contains(city)) {          // miss
        queue.add(city);
        answer += 5;
    } else if (queue.size() < cacheSize && queue.contains(city)) {    // hit
        queue.remove(city);
        queue.add(city);
        answer += 1;
    } else if (queue.size() >= cacheSize && !queue.contains(city)) {  // miss, 꽉 참
        queue.poll();
        queue.add(city);
        answer += 5;
    } else if (queue.size() >= cacheSize && queue.contains(city)) {   // hit
        queue.remove(city);
        queue.add(city);
        answer += 1;
    }
}
return answer;

// ---------- 게임 맵 최단거리 -> BFS (격자 최단거리, dist[][] + 4방향) ----------
// @tags: BFS, 그래프
// @hint: yes
// @solved: 2026-11-01
// @review: 2026-11-04, 2026-11-08
// @quiz: BFS 에서 각 칸까지의 최단거리를 기록하는 올바른 방법은? | dist[새칸] = dist[지금칸] + 1 | 큐에서 꺼낼 때마다 count++ | 큐에 넣을 때마다 count++ | 4방향을 다 볼 때마다 count++
// @why: 갈래가 여러 개라 count 하나로는 "꺼낸/넣은 칸 개수"가 섞임. 칸마다 자기 거리를 따로 저장해야 함 (count 를 쓰려면 queue.size() 만큼 한 겹씩 처리)
// BFS(너비 우선) vs DFS(깊이 우선)
//   DFS : 한 길을 끝까지 가보고 막히면 되돌아옴 (재귀 / Stack) -> 모든 경우, 순열/조합
//   BFS : 가까운 칸부터 한 겹씩 (1칸 -> 2칸 -> 3칸) 넓혀감 (Queue, FIFO) -> 최단거리
//   Queue 라서 먼저 넣은(가까운) 칸이 먼저 나옴 -> 거리 순서가 자동으로 지켜짐
// "최단거리 / 최소 칸 수" + 모든 칸 이동 비용이 같음 -> BFS
// BFS 는 1칸, 2칸, 3칸 ... 거리 순서대로 퍼짐 -> 도착점에 "처음" 닿는 순간이 최단거리
// DFS(완전탐색)는 모든 경로를 끝까지 가봄 -> 맞긴 해도 맵이 크면 시간 초과
// 틀 : Queue<int[]> 에 {행, 열} 넣기 + dist[][] 에 "여기까지 몇 칸" 저장 (dist 가 visited 역할도 함)
//      꺼낼 때마다 dx/dy 4방향 -> 범위 안 && 벽 아님 && 처음 방문이면 dist = 현재 + 1, 큐에 넣기
//      큐가 빌 때까지 도착점에 못 닿으면 -1
// 넣을 때 방문 처리해야 같은 칸이 큐에 여러 번 안 들어감
// dist[x][y] = 시작점에서 (x, y) 까지 몇 칸. dist[새칸] = dist[지금칸] + 1
//   꺼낼 때마다 count++ 하면 X : 그건 거리가 아니라 "꺼낸 칸 총개수" (갈래가 여러 개라 섞임)
//   count 를 쓰고 싶으면 int size = queue.size(); 만큼 한 겹 처리하고 겹이 끝날 때 count++
// 내 풀이 (canGo[][] = 갈 수 있으면 true, 넣을 때 false 로 바꿔 방문 처리)
Queue<int[]> queue = new LinkedList<>();
int[] dx = {0, 0, 1, -1};   // 동서남북 (x = 행, y = 열 -> 동서는 열(y)이 바뀜)
int[] dy = {1, -1, 0, 0};
boolean[][] canGo = new boolean[maps.length][maps[0].length];
int[][] dist = new int[maps.length][maps[0].length];
for (int i = 0; i < maps.length; i++)
    for (int j = 0; j < maps[0].length; j++)
        canGo[i][j] = maps[i][j] == 1;

queue.add(new int[]{0, 0});
dist[0][0] = 1;                 // 시작칸도 1칸으로 셈
canGo[0][0] = false;            // 시작칸 방문 처리

while (!queue.isEmpty()) {
    int[] cur = queue.poll();
    for (int i = 0; i < 4; i++) {
        int nx = cur[0] + dx[i];
        int ny = cur[1] + dy[i];
        if (nx < 0 || ny < 0 || nx >= maps.length || ny >= maps[0].length) continue;
        if (!canGo[nx][ny]) continue;
        dist[nx][ny] = dist[cur[0]][cur[1]] + 1;
        queue.add(new int[]{nx, ny});
        canGo[nx][ny] = false;  // 넣을 때 방문 처리
    }
}
int d = dist[maps.length - 1][maps[0].length - 1];
return d == 0 ? -1 : d;         // 0 이면 도착 못 함

// ---------- 프로세스 -> Queue<int[]>{인덱스, 우선순위} + "더 큰 게 남았나" 검사 ----------
// @tags: 스택/큐
// @hint: yes
// @solved: 2026-11-01
// @review: 2026-11-04, 2026-11-08
// @quiz: 꺼낸 프로세스보다 우선순위가 높은 게 큐에 남아 있으면 어떻게 할까? | 다시 큐 맨 뒤에 넣고, 실행 횟수는 그대로 | 다시 넣고 실행 횟수 +1 | 우선순위 높은 걸 찾아서 바로 실행 | priorities 를 내림차순 정렬해서 location 의 위치를 답으로
// @why: 뒤로 보낸 건 실행된 게 아니라서 세면 안 됨. 정렬하면 같은 우선순위끼리의 큐 순서가 사라져서 틀림
// 맨 앞을 꺼내서 뒤에 더 큰 우선순위가 있으면 다시 뒤로(add), 없으면 실행(count++)
// 실행한 게 location 이면 그때의 count 가 답 -> 바로 return (실행 순서 배열 따로 필요 없음)
// 핵심 : 원소가 뒤로 돌면 위치가 바뀌니까 "원래 인덱스"를 원소와 같이 저장
// 더 큰 값 검사 : queue.stream().anyMatch(p -> p[1] > cur[1])  (n <= 100 이라 매번 훑어도 충분)
// 심화 : 우선순위만 PriorityQueue(Collections.reverseOrder()) 에 넣어 두면 pq.peek() 가 "지금 최댓값"
//        실행할 때마다 pq.poll() 로 같이 빼기
Queue<int[]> queue = new LinkedList<>();               // {원래 인덱스, 우선순위}
for (int i = 0; i < priorities.length; i++) queue.add(new int[]{i, priorities[i]});
int proceed = 1;
while (!queue.isEmpty()) {
    int[] cur = queue.poll();
    if (queue.stream().anyMatch(x -> x[1] > cur[1])) queue.add(cur);   // 더 큰 게 있으면 뒤로
    else {
        if (cur[0] == location) return proceed;      // 실행된 경우에만 확인
        proceed++;
    }
}

// ---------- 튜플 -> 집합을 원소 개수 순으로 정렬하고, 새로 등장한 숫자만 차례로 담기 ----------
// @tags: 문자열, 정렬, 해시
// @hint: no
// @solved: 2026-11-02
// @review: 2026-11-05, 2026-11-09
// @quiz: "{{2},{2,1},{2,1,3}}" 같은 집합 문자열에서 튜플 순서를 알아내려면? | 집합을 원소 개수 순으로 정렬하고, 앞에서부터 새로 나온 숫자만 담기 | 숫자들을 전부 꺼내서 오름차순 정렬하기 | 문자열에 나온 순서대로 중복만 빼고 담기 | 각 집합의 첫 번째 숫자를 차례로 담기
// @why: 크기 k 집합 = 튜플 앞 k 개라서, 작은 집합부터 보면 매번 딱 하나씩 새 숫자가 생김. 입력은 집합 순서도 집합 안 원소 순서도 섞여 있어서 나온 순서/첫 원소/숫자 크기는 믿으면 안 됨
// 입력 순서는 뒤죽박죽 ("{{4,2,3},{3},{2,3,4,1},{2,3}}") -> 집합 크기로 정렬해야 순서가 생김
// 크기 1 집합의 원소 = 1번째, 크기 2 집합에서 새로 생긴 원소 = 2번째 ... (매번 정확히 1개만 새로 생김)
// 파싱 : 바깥 "{{" "}}" 를 substring(2, len - 2) 로 떼고, "},{" 를 구분자로 바꿔 split
// 문자열 길이로 정렬해도 OK : 다음 집합은 앞 집합 + 숫자 하나 + 쉼표 하나라서 항상 더 김
//   (더 안전하게 하려면 split(",").length 로 원소 개수 비교)
// 이미 담은 숫자는 HashSet 으로 걸러내기 (contains O(1))
// 다른 풀이 : 숫자마다 등장 횟수를 세면 많이 나온 숫자일수록 앞 (1번째 원소는 n 번, 마지막은 1 번)
String str = s.substring(2, s.length() - 2).replace("},{", "-");
String[] sets = str.split("-");
Arrays.sort(sets, (a, b) -> a.length() - b.length());   // 원소 적은 집합부터
int[] answer = new int[sets.length];
Set<String> seen = new HashSet<>();
for (int i = 0; i < sets.length; i++) {
    for (String num : sets[i].split(",")) {
        if (seen.add(num)) {                  // add 는 새로 들어가면 true
            answer[i] = Integer.parseInt(num);
            break;                            // 새 숫자는 딱 하나라 바로 끝
        }
    }
}

// ---------- 타겟 넘버 -> DFS 2갈래 (+ / -) 로 index 끝까지, 끝에서 합 비교 ----------
// @tags: DFS, 완전탐색, 재귀
// @hint: yes
// @solved: 2026-11-03
// @review: 2026-11-06, 2026-11-10
// @quiz: 숫자 최대 20개에 + 나 - 를 붙여 target 을 만드는 방법 수를 세려면? | 재귀로 숫자마다 +, - 두 갈래를 끝까지 다 시도 | 큰 숫자부터 빼며 맞추는 그리디 | for문으로 - 붙일 숫자 하나만 바꿔 보기 | 전체 합에서 target 을 빼고 2 로 나눈 값 하나만 확인
// @why: 2^20 = 약 100만이라 전부 해봐도 빠름. - 가 여러 개 붙는 경우도 있어서 하나만 바꾸면 빠지고, 그리디는 개수를 못 셈
// 숫자 순서는 고정, 고를 건 부호뿐 -> dfs(index, sum) 하나가 "index 번째 숫자의 부호 정하기"
// 호출마다 재귀 두 번 (더한 쪽, 뺀 쪽) -> 이진 트리, 깊이 n, 잎 2^n 개
// 왜 무한히 안 도나 : index 가 매번 +1 이라 n 에서 반드시 멈춤
// 원복 필요 없음 : sum 을 매개변수 새 값으로 넘기니까 돌아오면 이전 값 그대로 (피로도의 visited 와 다름)
// 피로도와 차이 : 순서를 고르면 for + visited (순열), 순서 고정에 선택만 하면 2갈래 재귀 (부분집합/부호)
// 종료 조건 : index == length 면 무조건 return, 합 비교는 그 안에서
void dfs(int[] numbers, int index, int currentSum) {
    if (index == numbers.length) {
        if (currentSum == sum) answer++;          // sum = target 을 필드에 저장해 둠
        return;                                   // 합이 달라도 여기서 끝
    }
    dfs(numbers, index + 1, currentSum + numbers[index]);
    dfs(numbers, index + 1, currentSum - numbers[index]);
}

// @hint: yes

// @quiz: 모음사전에서 word 가 몇 번째인지 구하는 방법은? | 빈 문자열부터 A~U 를 뒤에 붙이는 DFS 로 방문 순서를 세기 | 길이 5 단어만 만들어 정렬 후 indexOf | 각 글자를 5진법 자릿수로 보고 그대로 5진수 변환 | BFS 로 길이 1 단어부터 차례로 세기
// @why: 사전 순서 = DFS 전위 순회 순서 (A, AA, AAA ...). BFS 는 길이 순이라 사전 순과 다르고, 단순 5진수는 길이가 다른 단어를 못 셈
// 사전 순서 : A -> AA -> AAA -> AAAA -> AAAAA -> AAAAE ... 뒤에 붙였다가 다 보면 돌아와서 다음 글자
// 타겟 넘버(2갈래) + 피로도(for 갈래) 를 합친 모양 : 재귀 안에서 for 로 5갈래
// 타겟 넘버와 차이 : 끝(잎)에서만 세지 않고, 노드에 들어올 때마다 센다 (길이 1~5 단어 전부가 사전에 있으니까)
// 무한루프 안 남 : 길이 5 면 return 이라 깊이가 막힘. 전체 단어 수 5 + 25 + 125 + 625 + 3125 = 3905 개
// 원복 필요 없음 : cur + aeiou[i] 는 새 문자열이라 cur 는 그대로 (+= 로 바꾸면 substring 으로 되돌려야 함)
// 수학 풀이 (참고) : 자리별 가중치 781, 156, 31, 6, 1 -> 답 = 합(글자 번호 * 가중치) + 글자 수
// dfs 파라미터 정하는 법 : "지금 어디까지 왔는지" 알려면 뭐가 필요한가?
//   바뀌는 값 -> 파라미터 / 계속 같은 값 (target, numbers) -> 필드
//   타겟 넘버 dfs(index, sum) / 모음사전 dfs(cur) / 피로도 dfs(k, cnt)
//   재귀 호출에는 "한 걸음 나아간 값" 넘기기 : index + 1, cur + 글자, k - 소모
int answer = 0, count = 0;
String[] aeiou = {"A", "E", "I", "O", "U"};
void dfs(String cur, String target) {
    if (!cur.equals("")) count++;                 // 빈 문자열은 단어가 아님
    if (cur.equals(target)) { answer = count; return; }
    if (cur.length() == 5) return;
    for (int i = 0; i < 5; i++) {
        dfs(cur + aeiou[i], target);
    }
}

// ---------- 뒤에 있는 큰 수 찾기 -> 단조 Stack (답 못 찾은 인덱스를 쌓고, 큰 수가 오면 pop 하며 채우기) ----------
// @tags: 스택, 단조 스택
// @hint: yes
// @solved: 2026-11-06
// @review: 2026-11-09, 2026-11-13
// @quiz: 뒤에 있는 큰 수 찾기에서 Stack 에 넣어야 하는 것은? | 아직 뒷큰수를 못 찾은 원소의 인덱스 | 아직 뒷큰수를 못 찾은 원소의 값 | 지금까지 나온 최댓값 | 이미 답을 찾은 원소의 인덱스
// @why: answer[i] 를 채우려면 위치가 필요해서 값이 아니라 인덱스를 넣음 (값은 numbers[인덱스] 로 꺼내 비교). 최댓값 하나로는 "가장 가까운" 큰 수를 알 수 없음
// 이중 for문 : 최악 (내림차순 배열) O(n^2) -> n 100만이면 시간 초과
// 핵심 : Stack 안은 항상 값이 내림차순 -> 새 숫자는 맨 위부터 비교하면 됨
// 새 숫자 numbers[i] 가 맨 위 값보다 크면 -> 그 인덱스의 답은 numbers[i], pop. 반복 후 i 를 push
// answer 를 처음에 -1 로 채워 두면 끝까지 Stack 에 남은 것들은 따로 처리 안 해도 됨
// 각 인덱스는 push 1번, pop 1번 -> 전체 O(n)
// for 안에 while 이 있어도 이중 반복 아님 : while 은 pop 할 때만 돌고 pop 은 전체 n 번뿐 -> 반복문 겹수 말고 "전체에서 몇 번 도나" 세기
// Stack 대신 Deque<Integer> (ArrayDeque) 가 더 빠름
int[] answer = new int[numbers.length];
Arrays.fill(answer, -1);
Deque<Integer> stack = new ArrayDeque<>();
for (int i = 0; i < numbers.length; i++) {
    while (!stack.isEmpty() && numbers[stack.peek()] < numbers[i]) {
        answer[stack.pop()] = numbers[i];           // 맨 위 인덱스의 뒷큰수는 지금 숫자
    }
    stack.push(i);                                  // 지금 숫자는 아직 답 모름
}

// ---------- [1차] 뉴스 클러스터링 -> 두 글자씩 잘라 다중집합, 교집합은 찾으면 remove, 합집합 = A + B - 교 ----------

// @quiz: 다중집합 A = [AA, AA, BB], B = [AA, CC] 의 교집합 크기를 리스트로 구하는 방법은? | A 를 돌며 B 에 있으면 count++ 하고 B 에서 그 원소를 remove | A 를 돌며 B.contains 면 count++ | 둘 다 HashSet 으로 바꿔 retainAll | A 와 B 를 합쳐 중복 개수 세기

// HashMap 으로 개수를 세서 교 = min, 합 = max 합으로 해도 됨

    if (t.matches("[A-Z]{2}")) b.add(t);

// ---------- 더 맵게 -> PriorityQueue 에 다 넣고, 최솟값 < K 인 동안 두 개 poll 해서 섞은 값 offer ----------
// @tags: 힙, PriorityQueue
// @hint: yes
// @solved: 2026-11-11
// @review: 2026-11-14, 2026-11-18
// @quiz: 더 맵게에서 가장 작은 두 값을 반복해서 꺼내고 새 값을 넣는 데 알맞은 자료구조는? | PriorityQueue (최소 힙) | 매번 정렬하는 ArrayList | 처음에 정렬한 배열 + 인덱스 | Stack
// @why: 새로 섞은 값이 계속 들어오니 최솟값이 바뀜. 힙은 넣기/빼기 log n 으로 최솟값을 맨 위에 유지하고, 매번 정렬은 n^2, 처음 한 번 정렬은 새 값 자리를 못 맞추고, Stack 은 최솟값과 상관없이 마지막에 넣은 것이 나옴
// 힙 : 이진 트리에서 "부모 <= 자식" 만 지킴 (형제끼리 순서는 상관없음) -> 루트가 항상 최솟값
// offer : 맨 아래에 넣고 부모보다 작으면 위로 교환 / poll : 루트 꺼내고 마지막 원소를 루트로 올린 뒤 더 작은 자식과 아래로 교환
// 둘 다 트리 높이만큼만 이동 -> log n (100만 개도 약 20번)
// 정렬은 처음 한 번은 괜찮음 (n log n). 반복문 안에서 매번 정렬하면 n^2
// PQ 를 쓰면 처음 정렬도 필요 없음 (offer 할 때 알아서 자리 잡음)
// poll() 두 번 = 정확히 1등, 2등 (꺼낼 때마다 다시 정리). 내부 순서를 for-each 로 보면 정렬 안 되어 있음
// 끝난 뒤 실패 판단은 개수가 아니라 peek() < K
Queue<Integer> pq = new PriorityQueue<>();          // 기본은 작은 값이 먼저 (최대 힙은 Collections.reverseOrder())
for (int s : scoville) pq.offer(s);
int answer = 0;
while (pq.size() >= 2 && pq.peek() < K) {
    int min = pq.poll();
    int min2 = pq.poll();
    pq.offer(min + min2 * 2);
    answer++;
}
if (pq.peek() < K) return -1;                       // 더 못 섞는데 아직 K 미만
return answer;

// ---------- 땅따먹기 -> land[i][j] += 윗줄에서 j 열을 뺀 나머지 3칸 중 최댓값, 마지막 행 최댓값이 답 ----------
// @tags: DP
// @hint: yes
// @solved: 2026-11-12
// @review: 2026-11-15, 2026-11-19
// @quiz: 땅따먹기에서 시간 초과나 오답 없이 푸는 방법은? | 행마다 4칸 모두 "이 칸까지 최대 합" 을 누적하는 DP | 매 행 가장 큰 칸만 골라 내려가는 그리디 | 모든 경로를 재귀로 다 따라가는 완전탐색 | 열마다 합을 구해 가장 큰 열 고르기
// @why: 그리디는 지금 작게 골라야 나중에 큰 값을 밟는 경우를 놓치고, 완전탐색은 경로가 약 4^N 개라 시간 초과, 열 합은 같은 열 연속 금지를 어김. DP 는 행 x 4 x 3 번이라 빠르고 모든 경우를 반영
// DP : "여기까지 왔을 때의 최고 점수" 를 칸마다 저장하고, 다음 칸은 저장된 값만 보고 계산 (경로를 다시 따라가지 않음)
// 이중 for 문이 느린 게 아님. 행 10만 x 4 x 3 = 120만 번이라 충분히 빠름. 느린 건 경로를 전부 따라가는 4^N
// 같은 열 제외 : (j+1)%4, (j+2)%4, (j+3)%4 로 나머지 3칸 고르기 (또는 안쪽 for 에서 k == j 이면 continue)
// Java Math.max 는 인수 2개만 받음 -> 3개 이상은 중첩
// 새 배열 없이 land 에 바로 덮어써도 됨 (윗줄 값만 필요하니까)
for (int i = 1; i < land.length; i++) {
    for (int j = 0; j < 4; j++) {
        int max = Math.max(land[i-1][(j+1)%4], Math.max(land[i-1][(j+2)%4], land[i-1][(j+3)%4]));
        land[i][j] += max;
    }
}
int[] last = land[land.length - 1];
return Math.max(Math.max(last[0], last[1]), Math.max(last[2], last[3]));

// ---------- [3차] n진수 게임 -> 0부터 n진수로 이어 붙이며 인덱스 i % m == p-1 인 글자만 t개 담기 ----------
// @tags: 비트/진법, 문자열, 시뮬레이션
// @hint: yes

// @quiz: n진수 게임에서 문자열을 언제까지 만들면 되는가? | 길이가 t * m 이상이 될 때까지 (멈추는 기준은 글자 수) | 숫자를 t 개 변환할 때까지 | 숫자를 t * m 개 변환할 때까지 | 마지막 숫자를 미리 계산해서 그 숫자까지
// @why: 튜브는 m 글자마다 한 번 말하므로 t 번 말하려면 글자가 t * m 개면 충분. 숫자마다 글자 수가 달라 몇 번째 숫자에서 끝날지는 몰라도 됨
// 진법 변환 : Integer.toString(num, n) 은 10진수 -> n진수 문자열 (10~15 는 소문자라 toUpperCase 필요)
//             Integer.parseInt(문자열, n) 은 반대로 n진수 문자열 -> 10진수 int
// 튜브 차례 : 0부터 센 글자 인덱스 i 에서 i % m == p - 1
// 방법 1 : 길이 t*m 까지 다 만든 뒤 i = p-1 부터 m 씩 건너뛰며 t 개 담기
// 방법 2 (내 풀이) : while 안에서 붙이자마자 새 글자만 검사, t 개 되면 바로 return
StringBuilder sb = new StringBuilder();
String answer = "";
int num = 0, idx = 0;
while (true) {
    sb.append(Integer.toString(num, n).toUpperCase());
    for (int i = idx; i < sb.length(); i++) {
        if (i % m == p - 1) {
            answer += sb.charAt(i);
            idx = i + 1;                                  // 담은 글자 다음부터 검사
        }
        if (answer.length() == t) return answer;          // 담는 순간 검사 (while 끝에서 하면 t 를 건너뜀)
    }
    num++;
}

// ---------- 주식가격 -> 단조 Stack 에 안 떨어진 인덱스를 쌓고, 더 싼 가격이 오면 pop 하며 i - top ----------
// @tags: 스택/큐, 단조 스택
// @hint: yes
// @solved: 2026-11-16
// @review: 2026-11-19, 2026-11-23
// @quiz: 주식가격에서 i 초 가격이 j 초에 처음 떨어졌다면 answer[i] 는? | j - i | j - i - 1 | i 와 j 사이 가격 개수 | 떨어지기 전까지 유지된 가격 개수
// @why: 세는 것은 "흐른 시간" 이고 떨어진 j 초까지 이미 j - i 초가 흐름. 사이 가격 개수나 유지된 개수는 j - i - 1 이라 1 작음
// 답 = 가격이 떨어질 때까지 흐른 초 (떨어진 그 1초 포함). 끝까지 안 떨어지면 (n - 1) - i
// 방법 1 (내 풀이) : 이중 for, 뒤 가격마다 count++ 후 떨어졌으면 break -> 최악 O(n^2) 이지만 이 문제는 통과
// 방법 2 (정석) : 뒤에 있는 큰 수 찾기와 같은 단조 Stack
//   아직 안 떨어진 인덱스를 쌓아두고, 지금 가격이 맨 위 가격보다 작으면 pop 하며 answer[top] = i - top
//   끝까지 남은 인덱스는 answer[idx] = n - 1 - idx -> 전체 O(n)

// 단조 Stack 버전 (정석, O(n))
// 인덱스 = 시각(초). prices[2] = 3 은 "2초에 3원", answer[2] 는 "2초의 3원이 몇 초 버텼나"
// Stack = 답을 아직 모르는 가격들의 대기 명단 (아직 안 떨어진 인덱스)
// 새 가격 i 가 맨 위 가격보다 싸면 -> 맨 위 가격이 i 초에 떨어진 것 -> answer[top] = i - top 확정 (answer[i] 가 아님!)
// i 자신은 아직 답을 모르니 push 해서 대기
// 가격이 같으면 안 떨어진 것 -> 조건은 > (>= 아님)
// for 끝나고 남은 인덱스 = 끝까지 안 떨어짐 -> 마지막 시각 n-1 까지 버팀 -> answer[top] = n - 1 - top
// 예) [1, 2, 3, 2, 3]
//   i=0~2 : push -> [0, 1, 2]
//   i=3 (2원) : 맨 위 2초(3원) 보다 쌈 -> pop, answer[2] = 3 - 2 = 1. 1초(2원)는 같아서 멈춤, push -> [0, 1, 3]
//   i=4 (3원) : push -> [0, 1, 3, 4]
//   끝 : 4 -> 4-4=0, 3 -> 4-3=1, 1 -> 4-1=3, 0 -> 4-0=4  => [4, 3, 1, 1, 0]
int n = prices.length;
int[] answer = new int[n];
Deque<Integer> stack = new ArrayDeque<>();           // 아직 안 떨어진 인덱스
for (int i = 0; i < n; i++) {
    while (!stack.isEmpty() && prices[stack.peek()] > prices[i]) {
        int top = stack.pop();
        answer[top] = i - top;                       // 떨어진 시각 - 시작 시각
    }
    stack.push(i);
}
while (!stack.isEmpty()) {
    int top = stack.pop();
    answer[top] = n - 1 - top;                       // 끝까지 버팀 : 마지막 시각 - 시작 시각
}
